# CLAUDE.md

Summit 3.0 Homebase. A prototype of the learner homebase for Summit Public Schools' next model, built on a sandbox of 100 invented students. Copy this file to the repo root as CLAUDE.md.

## What You Are Building

One web app with four roles (student, mentor, content expert or facilitator, school lead) over one data model. The student's page is the product: progress toward outcomes, the plan for the week as time slots labeled by eight experience types, access to the learning resources, the line to the long-term plan in Futre, the mentor's guidance. Read the specs in `/specs` in order. Spec 1 is the data model; nothing adds an object without updating it. Spec 9 is the build plan and the rules for working unattended. Spec 10 is the knowledge graph.

## Design Principles (Non-Negotiable)

- Technology recommends. People decide. Every engine proposal has a human confirmer and a visible "why."
- Flexibility with predictability. The week is published Friday; overnight changes are small and the week holds.
- No lockstep, no grade levels. Lessons are assigned per student. Level is Expose, Explore, Pursue, or Launch and moves on evidence.
- Protected time is protected and its reason is never stored or shown.
- Asset language in every string a person reads. Describe what a student is building, never what they lack. "Needs a nudge," never "failing."
- The sandbox is the product for now. Every screen must respond to the seed data. Change a score, the week changes.

## Stack (Decided)

React 19, Vite, TypeScript, Tailwind v4, React Router, Zustand for state, Zod for schema validation, date-fns, Recharts. Vitest for unit tests, Playwright for one happy-path run per role. Deployed to Vercel as a static app. No backend in v1: the sandbox is JSON fixtures generated by `seed/generate.ts` and loaded into an in-memory store with a repository interface, so a real API drops in later. Google Fonts Arimo.

## Working Rules

- Decide every technical question yourself. Record each decision in one line in `DECISIONS.md`. Never stop to ask.
- Record product questions (copy, labels, screen priority, spec contradictions, scope, privacy) in `QUESTIONS.md` with your working assumption. Proceed on the assumption.
- Never add an object the data model does not have. If a screen needs one, add it to `specs/01-DATA-MODEL.md` first and note it in `DECISIONS.md`.
- Every string a student or adult reads lives in `src/copy/en.ts`. Spanish is a second file with the same keys; machine-draft it, mark it `needs_review`.
- No em-dashes in any copy. No "not X but Y" phrasing. Sentence case in body text, title case in screen titles.
- Brand: see `specs/08-DESIGN.md`. Arimo, teal `#508278` and indigo `#4b4b96` for headings, black body, the eight experience-type colors fixed as tokens.
- Commit after every phase in `specs/09-BUILD-PLAN.md` with the phase name in the message. Keep the build green at every commit.
- Run `npm run build && npm test` before each commit. If a test fails, fix it before moving on; if it cannot be fixed in 20 minutes, mark it `test.skip` with a `TODO` and a line in `QUESTIONS.md`.
